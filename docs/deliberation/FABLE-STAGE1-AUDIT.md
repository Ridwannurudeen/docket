# Fable 5 — Stage 1 code audit (pre-merge)

**Scope:** branch `feat/stage1-marketplace`, commits 0e44c5f, 43548c3, 6e70e85, 87bbf71, 254e9d1 on top of 8fc2798. Audited 2026-08-10 against the plan (`docs/plans/2026-08-15-stage1-marketplace-ontology.md`). The builder could not write its report file, so this audit is of the code alone; no builder claim was taken on trust that the code and data could not confirm.

**Method:** full suite run on the branch (349 passed, 31.4s); base collected in a throwaway worktree (256) and the worktree removed. The live `data/agents.sqlite3` was read only via `mode=ro`. The fact plane was diffed empirically: base and branch apps were both run against the same scratch copy of the live database and thirteen probes — every `/agents` filter, pagination, both error shapes, `/stats`, and the OpenAPI fragments for `/agents`, `/agents/{agent_id}`, `/stats` and all five fact-plane schemas — compared JSON-for-JSON. The app was then run on a scratch copy under uvicorn and driven in a real browser: home, both empty and stocked shelves, all three service pages, one live `POST /hire/range-doctor` against BSC RPC through the page's own form (result + receipt verified), the invalid-wallet failure path, the zero-argument form, the unknown-service 404, and the `/browse` redirect. One mutation run (delete the home's slice region, run the pinning tests, restore) proved the ordering test bites. `git status` is clean; nothing was pushed, deployed, or mutated.

## Verdict: MERGE WITH FIXES

Stage 1 does what it was chartered to do, and does it more honestly than the plan specified. The four non-negotiables all hold and are all test-enforced, the fact plane is byte-identical on the live data, the activation path works end-to-end against the real chain, and the builder's two verifiable errata against the plan are both exactly right — the plan's cross-link instruction would have shipped a dead promise, and the builder's three-state replacement is the strongest piece of design on the branch. One defect must be fixed before merge because it is this project's own signature defect class, and because the merge window is the only place the fix is free.

## Tier 1 — required before merge

### F1 (MEDIUM): the `/browse` 308 silently un-filters every shared filtered link

`docket/api/routes.py:414-419` redirects `/browse` to the string `/research` and drops the query. Verified live: `GET /browse?has_feedback=true&name_family=gembots` → `308 Location: /research`, filters gone; same for `?offset=50`. The query string is not incidental here — it is the product: app.js puts every filter in the URL precisely so "a narrowed view is a link someone can send" (`docket/api/web/app.js:792-793`, pinned by `test_research_reflects_its_filters_into_the_query_string`), and `/browse` was the deployed route those links were minted on. A reader's saved narrowed view now lands on the whole snapshot. The page does announce its own state ("No filter: the whole snapshot.", `app.js:916-917`), which is why this is medium and not high — but a narrowed request silently served wide is the exact defect class Stage 0's F1 (`?publisher=` un-filtering) was rejected for, and the branch even documents that standard in its own comment at `routes.py:103-105`.

The sharp edge is the status code: 308 is *permanent*, so browsers and intermediaries may cache the mapping per-URL. If `/browse?x=y → /research` (query gone) ever serves publicly, clients that cached it keep the broken target even after a later fix. The branch is undeployed, so no 308 has ever been served — merge is the last moment this fix costs nothing.

Fix: take `request: Request` in `browse()` and append `request.url.query` when present (`/research?` + query); extend `test_the_old_browse_url_moves_rather_than_breaking` (`tests/test_web_categories.py:65-71`) to assert an encoded query survives byte-for-byte. `/research` already reads the same parameter names, so a preserved query restores the filtered view with no other change.

## Tier 2 — recommended, non-blocking

### F2 (LOW): one in-app link still points at the retired path

`docket/api/web/app.js:1228`: the agent page's "no id given" panel links `href="/browse"`. It works via the 308 (and will keep working), but it is the only surviving `/browse` reference in shipped UI — `agent.html:49` was updated to `/research` in the same commit. One-word fix; also makes the F1 caching surface smaller.

### F3 (LOW): the rate guard is an open unit vocabulary in a codebase of closed ones

`Metric.__post_init__` refuses a bare value only when `unit` is in `SHARE_UNITS = {"%", "percent", "share"}` (`docket/marketplace/models.py:112, 147-151`), and the API-level test checks the same three strings (`tests/test_services_api.py:244`). A metric typed `unit="pct"` or `"percentage"` or `"success rate"` with no denominator would construct, serve, and render. Today this is theoretical — all six shipped metrics are proper fractions or genuine counts, verified against the experiment files by `test_the_timings_on_a_record_are_the_timings_in_the_experiment_it_cites` — but `activation` and `EVIDENCE_KINDS` are closed vocabularies with tests, and the unit of a figure is a stranger place to leave open than either. Cheapest hardening: extend `SHARE_UNITS` with the obvious synonyms (`pct`, `percentage`, `per cent`, `rate`, `ratio`, `share of`), or require value-only metrics to draw their unit from a closed set.

### F4 (LOW): the version query is pinned to exist, not to agree

`?v=2` is applied consistently today (all five pages, both assets — verified by grep), and `test_the_stylesheet_and_module_are_versioned_so_a_returning_reader_gets_them` (`tests/test_web_categories.py:220-231`) pins its presence. It does not pin equality, so the real returning-judge trap — a future partial bump leaving index.html on `?v=3` and agent.html on `?v=2`, two pages loading two cached generations of one `app.js` — is unguarded. Bump-on-change cannot be tested statically and stays manual (the docstring records why the mechanism exists: the builder measured a stale-cache failure); cross-page *equality* can be tested in five lines. Add it.

### F5 (LOW): a pre-existing journey test still walks the old map

`tests/test_advantage_report.py:224` iterates `("/", "/browse", "/agent", "/advantage")`, so it now tests `/research` only through the redirect and never visits `/service`. Coverage exists elsewhere (`test_every_page_carries_the_same_navigation` reads all five files statically), so this is staleness, not a hole. Update the tuple to the five real routes.

## The assigned questions, answered

**(a) The four non-negotiables held?** All four, each with teeth.

1. *No-verdict extended and value-level scanned:* all seven new models are in the contract test's `ALL_MODELS` (`tests/test_api_contract.py:26-36`); value-level scans run word-bounded over every string of every `ServiceRecord` including the rendered metric text (`tests/test_marketplace.py:323-333`) and over the full JSON of `/categories`, `/services` and every `/services/{id}` (`tests/test_services_api.py:252-260`). Manual read of every served sentence concurs; the only banned-adjacent words are explicit denials.
2. *Every rate carries a denominator, a rate Metric without one raises:* enforced in `Metric.__post_init__` (`docket/marketplace/models.py:143-153`) three ways — split fraction refused, share-unit-without-base refused, figureless metric refused — and pinned by five tests (`tests/test_marketplace.py:114-167`). `render()` puts the denominator inside the string ("14 of 14 position NFTs"); the API's `display` is that string (`routes.py:159-172`); the pages are pinned to paint `metric.display` and to never touch `metric.numerator` (`tests/test_web_categories.py:164-169`). Verified rendered: "14 of 14 position NFTs the wallet held", "1 of 4 vectors a manual read of the same text found", "382 of 384 receipts in the chain". Residual looseness is F3's open unit list.
3. *No invented category membership:* exactly one declaration exists — range-doctor → rebalancing (`docket/marketplace/registry.py:49-51`); warden-scan and solvent-signal carry `category=None` with the refusal reasoned in comments (`registry.py:117-120, 177-180`); `category_counts()` pins {1,0,0,0} (`tests/test_marketplace.py:365-374`). `CATEGORY_DECLARATION` travels on `/categories` and `/services` and is rendered on the home, the service page badge, and the research page's plane-separation note (verified live). `/agents` carries no category field (schema diff: none).
4. *Honest empty states:* three shelves serve `service_count: 0` plus the `EMPTY_CATEGORY` prose saying why, with no date; verified live — each renders "No service here yet. Docket lists a service only where it runs the work itself…", no placeholder card, no promise. Tests ban the promise words in the constant (`tests/test_marketplace.py:377-381`), in the API (`tests/test_services_api.py:93-107`), and across every web file (`tests/test_web_categories.py:106-111`).

**(b) Is /agents genuinely unchanged?** Yes, to the byte. Base and branch run against the same copy of the live database returned identical JSON on all thirteen probes — every filter combination, pagination, the 404, the retired-`publisher` 422, `?limit=abc`, and `/stats` — and identical OpenAPI fragments for both agent paths, `/stats`, and the `AgentSummary`/`AgentDetail`/`ListResponse`/`StatsResponse`/`Coverage` schemas. The OpenAPI path delta is exactly `+/categories +/services +/services/{service_id}`, nothing removed. Every diff hunk touching the existing handlers is line-joining reformatting. `test_the_raw_agent_plane_is_untouched_by_the_layer_above_it` pins the field sets against leakage.

**(c) The activation path.** Works end-to-end, verified live in a browser against real BSC RPC: home card → `/service?id=range-doctor` → form built from the served `input_schema` → the page's own submit handler POSTed `/hire/range-doctor` same-origin (`postJSON` takes paths only, and CORS stays GET-only so a foreign page cannot drive it — `app.js:107-110`, `routes.py:322-327`) → result rendered (limit=3 honoured: `positions_held: 15` beside `positions_examined: 3`, the bounded-read disclosure working) → receipt rendered with `input_hash` 0x6369…, `output_hash` 0xf183…, payment tier, and the "records delivery and nothing else" caveat. Limitations render on every service page ("What it cannot do"); warden-scan's page carries its 1-of-4 loss, the loss-naming evidence label, and the payload textarea; solvent-signal's zero-argument form says there is nothing to supply. No dead end found for a zero-knowledge user: bad wallet → typed `invalid_field` panel with the API's own message, "Nothing was charged", input preserved (verified); missing required field → client-side `missing_field` without losing input; unknown id → `service_not_found` naming `GET /services`; no id → typed panel routing home; JS off → noscript with the exact curl sequence. Zero JS console errors across every page driven; the only console entries are the browser's own logs for the deliberate 422/404 responses. All three evidence anchors (`/advantage#01-liquidity`, `#02-trading`, `#03-security`) resolve to real ids (`advantage.html:254, 567, 739`).

**(d) The /browse 308.** The right mechanism — moved not removed, one canonical target, method-preserving 308, redirect verified in TestClient and a real browser — with one real defect: the dropped query string (F1, required). Reference sweep: llms.txt and SKILL.md never documented `/browse` (it was `include_in_schema=False` all along), so no machine contract breaks; nav links on all five pages point at `/research`; the stragglers are `app.js:1228` (F2) and the stale test tuple (F5). Bare `/browse` links and bookmarks land correctly.

**(e) The builder's plan errata.** The two named claims verified true against the live database, read-only:

- *SOLVENT's identity is in no served snapshot:* 104,006 agent rows across all three snapshots, **zero** with token `:136384` (the address in every agent_id is the shared registry contract, so the token is the discriminator — the "matching" address count is all 104,006 rows). The builder's row count is exact. A `/agents/{id}` cross-link per the plan's Task 2 would 404 on the live deployment: a dead promise.
- *The plan's `0x8004A169…` casing would never match:* **zero** of 104,006 agent_ids contain an uppercase character; the store and API match case-sensitively. The plan's mixed-case id, followed literally, could never resolve even if the row existed.

So the builder was right to refuse the plan, and did not over-claim on either count. What it built instead is better than compliance: a three-state cross-link (`agent_path` null unless the identity is actually in the served snapshot, `identity_note` naming which case — `routes.py:135-152, 604-627`), lowercase-normalized storage with a case-insensitive lookup that links the *stored* id (pinned by `test_an_identity_stored_in_another_case_is_still_the_same_agent`), and all states tested — including, verified here empirically, the fourth no-snapshot state the tests skip: an empty database serves `/services/{id}` 200 with `IDENTITY_NO_SNAPSHOT` while `/agents` correctly 503s. The remaining four errata cannot be enumerated because the report was never written; the plan deltas I found independently — offer fields as read-through properties instead of the plan's copied field list (anti-drift, tested), the redirect the plan never asked for, Task 4's bindings folded into the ontology commit rather than a fourth feat commit — are all judgement in the right direction, none hidden from the diff.

**(f) Cache busting.** Manual but consistent today — `?v=2` on both assets across all five pages, nothing unversioned, nothing stale — and the mechanism is the right one for a no-build-step site whose static server sends no Cache-Control (the docstring records the measured stale-CSS failure that motivated it). The unguarded trap is a future partial bump (F4); the discipline itself cannot be automated away without a build step.

**(g) Thesis regression.** None found. No number lost its denominator: every home figure re-verified rendered with its base, and the Stage 0 fixes survive intact — "A request was issued" phrasing, the lower-bound `registry_total` sentence, the population-gated census branch, and the slice disclosure all present live. No claim outruns evidence: the new copy's strongest claims ("can show a recorded run behind it") are backed by the evidence links, and the unflattering figures survive to the shop front itself — the home card shows warden-scan's "1 of 4 vectors" and solvent-signal's past-the-anchor caveat lands in its limitations. No verdict word in any served string (scans + manual read). The move-not-delete claim was mutation-tested: deleting the home's slice region fails two independent tests (`test_the_home_leads_with_the_jobs_and_keeps_the_evidence_beneath_them`, which pins both presence and jobs-first ordering of the stats/slice/families regions, and `test_landing_states_the_sampled_figure_is_a_filtered_slice`); the file was restored and the tree is clean. Diffing every line removed from index.html: each honesty sentence either moved intact ("None of them is a count of working agents", the noscript grew two paths) or was strengthened ("It does not rate, rank or vouch" → "Docket rates, ranks and endorses nothing"); the only true deletion is the old indictment headline, which is the copy shift the plan ordered.
